## 人物写法

每个人至少有一项工作以外的偏爱、一处会惹出小麻烦的习惯，以及一位不经玩家也会往来的熟人。职业决定他首先注意什么，不决定每句话都在教玩法。旧故事里已经写过害怕、遗憾的角色，后续要给他普通的一天：讨价还价、记错名字、攒小物件、嫌茶太浓都可以。

每次日常交谈通常1～2句；一个故事节点先交代眼前具体的事，再让玩家回应。长段拆成有语义的页，不把一句话硬切断。不要所有人都说“你让我明白了”“这不是……而是……”或为普通小事总结人生道理。转折来自证据变化、错认、利益冲突和人物自己的行动，不靠每条线都揭露伤痛。

人物可以有意见、不喜欢玩家的经营方式、拒绝某次邀请；这些反应有具体原因，不把关系值低写成机械辱骂。亲密后会省掉客套、提起共同经历，不能所有人统一追加“看到你就安心”。对关系的透露优先用一件小事：“乔信又把左脚木屐落下了”，而非列出一串好感关系。

## 关系记账

关系分三种证据，写作时不可混用：

1. **既有**：已在0.17场景、日程、短篇中说明。例如顾星借贺木工坊、许棉借林穗柜台、汤禾替乔信保管木屐。
2. **待表现**：本目录补充的日常爱好或熟人摩擦。接入相应对白后才成为玩家可知事实。
3. **待定**：岑婆等新角色的家人与住所、尚无机制支持的合同与竞争。不能拿待定身份推翻已发生剧情。

共用一间住宅不等于亲属、伴侣或监护关系。NPC之间的友谊也不自动变成玩家的好感。世界事件与玩家私人谈话分开：伙伴修好了灯，镇民都能看见；伙伴向陆舟说过什么，其他玩家不能冒领。

## 本轮日常对白接入边界

`ResidentDialogue`只读已有数据，按游戏日与稳定角色顺序选择两句基础话题；有真实进展时，把一条回访加入同一个轮换池，因此完成短篇后也不会每天只说结局。相同日次、人物与进展得到相同文本，不靠反复点击刷新候选。

`Journal.talk`继续每天每人对每位NPC只增加一次2点好感。已有 `talked` 不含该NPC时，先返回原职业介绍；下一次开始使用日常话题。原存档已经聊过的人不重新自我介绍。岛上服务时间、租约/领取/交易动作和海中潮语门槛保持原处理。原通用高好感寒暄已去除。

本轮**不增加存档字段**，不记录某句是否听过、不实现经营倾向/路线选择；无 `stories` 的旧数据不会被当作已经完成短篇。许岸按当前玩家是否已领取工具说话；贺木读施工/修好/实际迁居；林穗只知道店已租，不声称尚未发生的首夜收入。陆舟、田青、许棉的回访读取本人原结局索引，其余人的回访兼容双方结局。

源码：`scripts/resident_dialogue.gd`、`journal.gd`、`island_town.gd`、`ocean_residents.gd`。专门规则检查在 `tests/resident_dialogue_checks.gd`；当前文档登记的是接入范围，实际运行结果由交付验证记录维护。

## 后续日常对白选择规格（尚未完整实现）

候选对白按下列优先顺序选择，一次只取一个主要话题：

| 顺位 | 类型 | 举例与限制 |
|---|---|---|
| 1 | 正在处理的事务结果 | 满包、材料不足、刚付租金；结果直接显示，不被闲聊盖住 |
| 2 | 本人刚完成的故事回声 | 只读当前 `slot` 的结局；优先说一次，之后进入偶尔出现的回忆池 |
| 3 | 当前实际世界进展 | 小屋施工/完工、店已租、灯已修；施工未完不能恭喜搬家 |
| 4 | 已确认的私人关系 | 针对本人好感与自己听过的话题；不从伙伴档案猜测 |
| 5 | 季节、时段、地点 | 使用真实游戏日历与所在场景；不可把离线天数当岛上经过的天数 |
| 6 | 职业小事、爱好、熟人 | 轮换基础对白；不要求玩家接任务才能听见 |

同一天反复点同一人，不能刷出几十次“首次见面”和额外奖励。本轮已按游戏日和角色顺序稳定轮换，个人进度决定候选池；未来需要保证“只说一次”的事件句必须记录已听ID，不能用随机数冒充记忆。**后者是待实现字段，现有v16存档没有日常对白已听表。**

事务按钮保留明确价格、材料和地点。正文负责人物说话，不把“按B、按E、好感+20、格子数”硬塞进每段寒暄。需要机制解释时让玩家主动选“怎么做”，退出后仍能再次问。海上/水下沿用相同说话人、正文、回应层次，不能在另一场景改成调试提示。

## 可读取的现有状态

以下字段已在源代码存在；具体值以运行中主机快照为准。

| 条件简称 | 现有状态 | 文本能知道的范围 |
|---|---|---|
| 院子已租 | `island.homestead.rented` | 共享租约；不等于已经开垦或已经领取工具 |
| 本人已领 | `island.homestead.claimed[slot]` | 当季种子×6、锄头、水壶成功入本人的包；满包不能预先标记 |
| 小屋已修 | `housing.level >= 1` | 房屋可用；`ready_day > 0`仍可能为扩建施工，要选准确的句子 |
| 贺木住筏 | `housing.carpenter` | 贺木实际位于船屋，不能仍要求去岛上工坊找他 |
| 店铺已租 | `restaurant.rented` | 可备料；不代表曾开门、卖出一份菜或赚钱 |
| 正在营业 | `restaurant.open` | 当前营业，不等于长期经营路线已选择 |
| 上次店铺结果 | `restaurant.last` | 必须先按现有结构核对日次和服务数据，再写“昨晚”；没有结果不能猜 |
| 灯已修 | `journal.story_step >= 1` | 共享世界事实；不会自动给另一玩家私人感谢 |
| 认识潮语 | `journal.tide_speech` | 当前语言能力共享；海中角色可以正常交谈 |
| 已学法术 | `journal.spells.rain / breath` | 只能提已存在的唤雨/潮息，不承诺传送、瞬熟或新战斗魔法 |
| 本人短篇完成 | `stories[slot][npc].step == 3` | 可读同一记录的 `choices[2]` 回应；未记录视为未听过 |

新长线不能塞进现有固定3段 `stories` 里覆盖旧条目；先设计独立、版本化记录，严格恢复未知ID/阶段/选项，迁移仅补缺省值。脚本通过后才决定最小的数据结构。

## 节点脚本模板

每个准备实装的节点必须写全下列信息，不能只有背景梗概：

```text
ID / 对应TODO / 脚本版本 / 设计或已接入
进入条件：真实状态；本人或世界；遇见地点；谁知道这件事
出场：NPC实际日程地点；不为演出瞬移居民或玩家
正文：分说话人、分页面；可选演出单独列明
回应：玩家原话 → NPC即时答复 → 下一节点/记忆
结果：本人物品、共享金币、个人关系、世界改变分别列出
推迟/退出：关闭不默认选项，不扣费；何时可重试
并发：两人同聊、先后交付、断线与迟到回复怎么处理
旧档：已有成果如何跳过；缺少历史记忆时说什么
验收：实际输入到结局/回访，存读、取消、满包、双人
```

回应可以改变后续台词、来访安排、菜单或合作对象；若只是结尾措辞，应明说是“记忆分歧”，不要包装成重大世界分支。决定共享设施/钱袋时写清成本与双方影响，重要的长期合同未来需要双方确认或可撤回安排；当前个人对话不能替伙伴签长期独占合同。

## 四条生活路线的共同边界

四条路线可兼修、暂停、重拾。玩家可以一直只开一家店，也可以不经营，仍然出海、种地、修屋。木匠学习不锁基础建造，魔法不锁普通探索，商业路线不移除种子/医疗/基础工具供应。

每条长线先写一段可从现有玩法走通的生活链，再决定新增系统。一次推进只要求明确的自然行为，不用隐藏总进度迫使玩家刷完所有NPC短篇。已完成短篇可以提供额外对白，但不能把23篇全完成设为任何路线前置。

## 文本与运行验收

- 写入前核对角色称谓、现有结局与TODO；写入后核对玩家读到的每个承诺是否真有对应机制。
- 文字稿完成只代表可评审。对话框两尺寸、海陆两类场景、名字与正文不互压、长回应可读、鼠标/键盘/取消都要在实装后验证。
- 主机校验人物距离、场景、语言条件和阶段；客户端只发送选择。失败不吞材料，重复请求不重复奖励，关闭对话后迟到回复不重新开窗。
- 正常游玩时至少看见一次后续变化，另验本人/伙伴归属、跨天、保存继续、旧档已经领先。关卡或声音演出尚未做时保留“待表现”，不能只以日志计完成。
